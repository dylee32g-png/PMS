## 1. 두 방식 한눈에 (그림)

```
[NAS 방식 — 복귀 대상]                      [오피스365 방식 — 중단]
담당자: NAS 폴더의 엑셀을 수정              담당자: OneDrive 웹 엑셀 수정
읽는 쪽: List 화면(브라우저)이 직접 읽음     읽는 쪽: NAS Docker 프로그램(pms-reader)이
  · PC마다 '폴더 읽기 허가증' 1회             15분마다 클라우드(Graph)를 읽음
  · 메인 PC 30분 주기 + 화면 진입 1회        [엑셀 열기] = 웹 엑셀(webUrl)
  · [엑셀로 열기] = WebDAV(.bat 1회)         [지금 확인] = 리더 요청(20초)
완성·검증: 7/22~7/28                        구축: 7/29~8/3 (오늘 중단 결정)
```

- 규칙(`_extSync.rules` — 대상 칸·파일조각·시트·셀·평균/합계)은 **두 방식이 똑같은 것을 씀**. 등록 화면(파란 칩 → 모달)도 같음. 다른 건 "누가 파일을 읽느냐"뿐.

## 2. 내일 작업 순서 (STEP 0 → 6, 이 순서대로)

### STEP 0 — 시작 전 확인 (1분)
- OneDrive `PMS진척자료` 폴더의 파일 **수정 시각**만 훑어보기: 테스트 기간(7/29~8/3)에 실무 수정이 클라우드에만 들어간 파일이 있으면 NAS로 복사. (원본은 원래 NAS에 있으므로 보통은 할 일 없음)

### STEP 1 — 오피스365 리더 중지 (★맨 먼저)
- NAS DSM → Docker → **pms-reader 컨테이너 중지** (삭제 아님 — 재도입 대비 보존. 폴더 `/volume1/docker/pms-reader`, main.py 백업 2개 있음).
- 먼저 끄는 이유: 전체 삭제·재등록 중에 리더가 옛 규칙대로 값을 다시 써넣는 사고 방지.

### STEP 2 — 코드 스위치 복귀 (딱 한 줄) + 배포
- 파일: `src/components/projectListData.js` **318행** → `export const NAS_SYNC_ENABLED = false;` → **true**
- `RULE_UI_ENABLED = true`(333행)는 **그대로 둔다** — 규칙 칩·모달의 공용 화면 스위치라 끄면 NAS 모드에서도 칩이 안 보임.
- 코드 주석(300~317행)에 "true로만 바꾸면 원래 기능 복구, 폴더 허가증만 PC별 재지정" 복구 방법이 명시돼 있음 (7/30 비활성화 때 보존 설계).
- 빌드·배포는 팀장님 VS Code에서: `npm run build` → `firebase deploy --only hosting` (샌드박스 빌드 신뢰 금지 — 루틴 규칙 2).
- 배포 후 1분 눈 확인: 행 칩 클릭 → 모달 제목이 **"NAS 진척자료 자동 연결"**로 보이면 정상 (오피스365 문구·자동 반영기 상태줄은 자동으로 숨음 — 코드의 `NAS_SYNC_ENABLED` 분기 확인 완료).
