## 5. ★NAS 보안 4겹 + VPN 서버 구축 (팀장님 실기기, 단계별 가이드로 완료)
1. 새 관리자 `necon-kr26` 생성(administrators) → 로그인 검증 → **admin 비활성화** (DSM 경고도 해소. 직원 CIFS 접속은 전부 NECONSYS 계정임을 확인 — admin 의존 없음)
2. 로그인 자동 차단 **5회/5분** + 허용 목록 사내 대역 192.168.0.1~254
3. VPN Server 설치(볼륨1) → OpenVPN 활성화 — UDP 1194 · **"클라이언트의 서버 LAN 액세스 허용" 체크(핵심)** · 압축 on · 나머지 기본
4. VPN 권한 = **necon-kr26 하나만** (PPTP·L2TP 전체 해제, NECONSYS·pms·umccfg 해제)
5. 공유기(SRM) 포트 포워딩 **외부 21194/UDP → 192.168.0.110:1194** 딱 1개 (비표준 포트 = 팀장님 아이디어)
6. .ovpn 수정: `remote necon-pj.synology.me 21194`
- 부수 발견(추후 검토): ① **Office-PC_VNC 외부 45900 활성** — VPN 정착 후 VPN 경유로 바꾸고 규칙 삭제 권장 ② UPnP 자동 개방 다수 ③ 5000/5001 외부 직접 개방은 없음(정상).

## 7. ★Office 2010 대응 — 제한 발견과 해법 (테스트 노트북 = XNOTE, Office 2010)
- 문제1: [엑셀로 열기]의 `ms-excel:` 신호는 **Office 2013부터** — 2010은 원천 불가.
- 해법1: **통역사 방식** — ms-excel 신호를 가로채 주소만 뽑아 Excel 2010에 전달하는 JScript를 HKCU 프로토콜로 등록(관리자 불필요, https 아니면 실행 안 하는 안전장치, 해제 .bat 동봉).
- 문제2(대발견): 웹주소(626자)를 UNC로 바꿔도 _CNS 공용 파일만 실패. 탐색기 더블클릭도 동일 에러 → **Excel 2010의 218자 제한은 한글=2자(바이트) 기준**임을 실측으로 규명: 진척자료 **212바이트=성공** vs _CNS **244바이트=실패** (문자 수로는 둘 다 218 이하라 착시).
- 해법2(v3): 경로 앞 74자(`\\192.168.0.110\NECONSYS_PJ\001 Project\001 파주\107 기술2팀 2026년 Project`)를 **P: 드라이브로 접기** — net use 자동 연결 + 통역사가 P:로 치환(파일 존재 확인 후, 실패 시 원 UNC 폴백) → _CNS **171바이트 → 성공**. 진척자료·공용 파일 모두 열기·저장 확인.
- 산출물: `운영가이드/PMS_엑셀열기_1회준비_Office2010.bat`(v3 — 통역사+P: 연결+블랙박스 로그 %APPDATA%\PMS\last_open.txt) + `PMS_엑셀열기_Office2010_해제.bat`. 검증: URL 추출 시뮬 7/7 · URL→UNC 변환 5/5 · 바이트 계산 실측 대조 · CP949+CRLF.
- **보고용 결론: [엑셀로 열기] = 2013 이상 기본 지원 / 2010 = 전용 .bat 1회로 지원 (전 버전 커버)**.
