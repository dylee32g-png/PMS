# PMS 진척자료 클라우드 자동 반영기 — NAS 설치 안내

2026-07-30 작성

---

## 이게 뭘 하나

```
15분마다 (설정 가능)

  NAS 안의 프로그램
      ├─ ① Microsoft에 토큰 요청        ← 사람 로그인 없음. 앱 권한으로
      ├─ ② 오피스365 클라우드 엑셀을 직접 읽음   ← 동기화 안 기다림
      ├─ ③ PMS와 똑같은 규칙으로 계산 (PLC · ETOS · 하위 공종표)
      └─ ④ 값이 달라졌으면 Firestore에 기록
                ↓
        직원 PMS 화면에 즉시 반영 (직원은 아무것도 안 함)
```

**없어지는 것**: 공용 PC 상주 · 브라우저 탭 열어두기 · 폴더 허가증 · 동기화 대기

---

## 준비물 4개

| 파일 | 설명 | 누가 |
|---|---|---|
| `main.py` | 프로그램 본체 | 제공됨 |
| `requirements.txt` | 필요한 라이브러리 목록 | 제공됨 |
| `docker-compose.yml` | 실행 설정 | 제공됨 |
| `config.json` | **비밀키를 넣는 설정 파일** | 제공됨 (빈칸 채우기 필요) |
| `firebase-key.json` | Firebase 서비스 계정 키 | **팀장님이 발급한 JSON 파일을 이 이름으로 바꿔서** |

---

## 1. NAS에 폴더 만들고 파일 올리기

DSM → **File Station** 열기

```
docker  (공유폴더 — Docker 설치하면 자동 생성됨)
  └─ pms-reader        ← 이 폴더를 새로 만드세요
        ├─ main.py
        ├─ requirements.txt
        ├─ docker-compose.yml
        ├─ config.json
        └─ firebase-key.json     ← 다운로드한 Firebase 키 파일을 이 이름으로 변경
```

전체 경로는 `/volume1/docker/pms-reader/` 가 됩니다.

> Firebase에서 받은 파일명이 `techteampms-firebase-adminsdk-xxxxx.json` 이라면
> **`firebase-key.json`** 으로 이름을 바꿔서 올려주세요.

## 2. config.json 채우기

File Station에서 `config.json` 우클릭 → **텍스트 편집기로 열기**

한 곳만 바꾸면 됩니다.

```json
"client_secret": "여기에_Entra에서_복사한_비밀키_값을_붙여넣으세요"
                  ↑ 아까 메모장에 복사해둔 값으로 교체
```

나머지는 이미 채워져 있습니다. 확인만 해주세요.

| 항목 | 값 | 확인 |
|---|---|---|
| `tenant` | neconsyspms.onmicrosoft.com | |
| `client_id` | 583ff4a8-dc8e-4114-9a05-9d57b5d2098f | |
| `drive_user` | jeep@neconsyspms.onmicrosoft.com | 진척자료 엑셀이 있는 OneDrive 주인 |
| `folder` | PMS진척자료 | OneDrive 안의 폴더 이름 |
| `team` | 기술2팀 | |
| `interval_min` | 15 | 몇 분마다 확인할지 |
| `dry_run` | **true** | **처음엔 true 로 두세요** (읽기만 하고 안 씀) |

---

## 3. Docker에서 실행

DSM → **Docker** → 왼쪽 **프로젝트** → **생성**

| 항목 | 값 |
|---|---|
| 프로젝트 이름 | `pms-reader` |
| 경로 | `/docker/pms-reader` |
| 소스 | **기존 docker-compose.yml 사용** |

**다음 → 완료** 하면 자동으로 시작됩니다.

첫 실행은 라이브러리를 내려받느라 1~2분 걸립니다.

## 5. 실제 반영 켜기

로그가 정상이고 숫자가 맞으면, `config.json` 에서

```json
"dry_run": true     →     "dry_run": false
```

로 바꾸고 Docker에서 컨테이너 **재시작**하면 실제로 Firestore에 기록됩니다.

---

## 문제가 생기면

로그에 `★` 로 시작하는 줄이 원인입니다.

| 로그 메시지 | 원인 · 조치 |
|---|---|
| `config.json 에 아직 안 채운 항목` | 비밀키를 안 넣었습니다 |
| `토큰 발급 실패 401` | 비밀키가 틀렸거나 만료됨 → Entra에서 재발급 |
| `Graph 403` | 애플리케이션 권한 `Files.Read.All` 관리자 동의 확인 |
| `Graph 404` | `drive_user` 또는 `folder` 이름 오타 |
| `시트 '...' 없음` | 엑셀 시트 이름이 바뀌었는지 확인 |
| `셀 ... 값이 숫자가 아님` | 해당 칸에 글자가 들어갔습니다 (예: `1` 대신 `100%` 로 입력해야 함) |
| `Firebase 키 파일이 없습니다` | `firebase-key.json` 이름·위치 확인 |

## 보안 메모

- `config.json` 과 `firebase-key.json` 은 **NAS 밖으로 나가면 안 됩니다.** 메일·메신저 금지
- 이 두 파일이 있는 `pms-reader` 폴더는 일반 직원이 접근 못 하게 권한을 제한하세요
  (File Station → 폴더 우클릭 → 속성 → 권한)
- Entra 비밀키는 24개월 뒤 만료됩니다. 만료 전에 재발급 필요 (달력에 표시해두세요)
