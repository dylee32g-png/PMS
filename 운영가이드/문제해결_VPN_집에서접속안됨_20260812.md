# VPN 집에서 접속 안 됨 — 오늘 밤 테스트 가이드 (2026-08-12)

증상: 집에서 OpenVPN 연결 시 **"Trying to connect(재시도)"만 반복**.
참고: 8/10 사무실 테더링 테스트는 성공 → 서버 자체는 정상이었음.

"재시도 반복" = 신호가 회사 서버까지 **아예 도달하지 못하는** 증상.
(계정 문제면 재시도가 아니라 AUTH_FAILED 라고 뜸)

---

## 0. 원인 후보 (유력한 순서)

| 순위 | 원인 | 왜 의심되나 |
|---|---|---|
| ★1 | **회사 공인 IP가 바뀜** | 회사 인터넷=유동 IP. `.ovpn`엔 8/10 시점 IP가 숫자로 고정. KT 유동 IP는 며칠~몇 주 단위로 바뀜 → 8/10 테더링 땐 맞던 주소가 지금은 다른 주소일 수 있음 |
| 2 | **자동 차단에 걸림** | NAS 보안 = 5회/5분 실패 시 그 IP 차단. 집에서 여러 번 재시도했다면 집 IP가 차단됐을 수 있음 |
| 3 | 서버/포워딩 이상 | VPN Server 꺼짐, 공유기 21194 규칙 삭제 등 — 테더링 성공 이력이 있어 가능성 낮음 |

---

## 1. 퇴근 전 사무실에서 준비 (5분)

- [ ] **① 회사 현재 공인 IP 메모** — 사무실 PC 브라우저에서 `ip.pe.kr` 접속 → 나오는 숫자(예: 222.101.xxx.xxx)를 휴대폰 사진/메모
- [ ] **② DDNS가 최신인지 확인** — 사무실 PC cmd 창:
  ```
  nslookup necon-pj.synology.me 8.8.8.8
  ```
  마지막에 나오는 Address가 ①과 **같으면** = DDNS 정상 (집에서 이걸로 현재 IP를 알아낼 수 있음)
  ①과 **다르면** = DDNS가 낡음 → ①의 숫자가 진짜. 사진 필수.
- [ ] **③ 자동 차단 목록 비우기** — DSM(192.168.0.110:5000) → 제어판 → 보안 → 계정 → **자동 차단** → [차단 목록] 열어 **모두 제거** (집 IP가 이미 차단돼 있을 수 있음 — 여기 지워야 오늘 밤 시도 가능)
- [ ] ④ VPN Server 켜져 있는지 — DSM → VPN Server → OpenVPN **실행 중** 확인
- [ ] ⑤ (선택) 공유기 확인 — Synology Router(192.168.0.1:8001) → 포트 전달 → **외부 21194 → 192.168.0.110:1194 (UDP)** 규칙 존재
- [ ] ⑥ **`.ovpn` 파일을 메모장으로 열어 `remote` 줄 사진** — `remote <숫자IP> 21194` 형태일 것

## 2. 집에서 진단 순서 (STEP 1→6, 위에서부터)

### STEP 1. 집 인터넷 정상 확인
브라우저로 아무 사이트나 열리면 통과.

### STEP 2. 회사의 '지금' IP 알아내기
집 PC cmd 창:
```
nslookup necon-pj.synology.me 8.8.8.8
```
→ 나온 Address = 회사 현재 IP (사무실 ②에서 DDNS 정상이었다면 신뢰 가능).
DDNS가 낡았다고 확인됐다면 → 퇴근 전 사진 찍은 ①의 숫자를 사용.

### STEP 3. `.ovpn`의 remote와 비교 ★여기가 유력 지점
`.ovpn` 파일을 메모장으로 열어:
```
remote  <IP>  21194
```
- STEP 2의 IP와 **다르면 → 이게 원인.** IP를 고쳐 저장:
  ```
  remote <STEP2에서 나온 IP> 21194
  ```
  포트가 1194로 되어 있어도 틀린 것 → **반드시 21194**.
- `setenv CLIENT_CERT 0` 줄이 있는지도 확인 (없으면 인증서 오류 남 — 8/10 정리본엔 있음).

### STEP 4. 프로필 재등록 후 연결
OpenVPN은 파일을 고쳐도 **이미 등록된 프로필엔 반영 안 됨**:
1. OpenVPN 앱에서 기존 프로필 **삭제**
2. 수정한 `.ovpn` 다시 가져오기(Import)
3. 연결 — 계정: `necon-kr26` (+ 비밀번호)

### STEP 5. 그래도 재시도 반복이면 — 로그 읽기
- Windows OpenVPN GUI: 트레이 아이콘 우클릭 → **View Log**
- 판독표:

| 로그에 보이는 것 | 뜻 | 조치 |
|---|---|---|
| `TLS Error: TLS key negotiation failed ... 60 seconds` | 신호가 서버에 못 닿음 | IP 재확인(STEP2~3)·차단 의심(STEP6) |
| `AUTH_FAILED` | 계정/비번 틀림 | necon-kr26 비번 확인 (재시도 5회 넘기지 말 것 — 차단됨) |
| `Connection reset` / `Network unreachable` | 집 회선 문제 | 폰 테더링으로 바꿔 1회만 시도 → 되면 집 공유기/통신사 UDP 문제 |

### STEP 6. 차단 의심 — 시도 횟수 관리
- 오늘 이미 여러 번 실패했다면 **집 IP가 자동 차단됐을 가능성**. 차단 해제는 **사무실 DSM에서만** 가능(내일 아침 1-③).
- 회피 요령: **폰 테더링(다른 IP)으로 1회 시도** → 테더링으로는 되는데 집 와이파이로는 안 되면 = 집 IP 차단 확정.
- 오늘 밤은 **IP 확인·수정을 끝낸 뒤에** 연결 시도 (막 누르면 5회 차단만 쌓임).

## 3. 재발 방지 (다음에 사무실에서 — 권장)

`.ovpn`의 remote를 숫자 IP 대신 **도메인**으로 바꾸면 유동 IP가 바뀌어도 자동 추적:
```
remote necon-pj.synology.me 21194
```
- 전제: 사무실 ②에서 DDNS가 최신으로 확인된 경우만.
- ⚠ 이 도메인 버전은 **외부 전용** — 사무실 안 PC는 hosts 고정(192.168.0.110) 때문에 이 파일로 테스트하면 안 붙는 게 정상 (8/10 확인 사실). 사무실 점검용은 지금처럼 숫자 IP 버전 유지.
- 해외 직원 배포본도 도메인 버전으로 바꾸면 "IP 바뀔 때마다 파일 재배포" 문제가 사라짐.
