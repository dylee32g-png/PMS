# VPN 접속 안 됨 — 문제 해결 (v2.0 · 2026-09-18)

외부(집·해외·테더링)에서 회사 NAS에 붙을 때 생긴 문제와 **실제로 해결된 방법**만 모았습니다.
v1(2026-08-12)은 아직 원인을 찾던 중의 점검표였고, 이 문서는 **2026-09-18 전 구간 성공**으로 끝난 결과본입니다.
→ 옛 문서는 `_구버전(보관)/문제해결_VPN_집에서접속안됨_20260812.md`

---

## 0. 먼저 — 증상으로 갈래를 나눈다

**이 한 줄이 절반입니다.** 증상마다 원인이 완전히 다릅니다.

| 화면에 뜨는 것 | 뜻 | 어디로 |
|---|---|---|
| `Missing external certificate` | 신호는 갔는데 **파일 설정**이 잘못됨 | **1장** |
| `Trying to connect…` 만 반복 | 신호가 **회사까지 아예 못 감** | **2장** |
| `Authentication failed` / `AUTH_FAILED` | **회사 서버까지는 도달함**(= 절반 성공). 계정 문제 | **3장** |
| `Securely Connected!` 인데 NAS가 안 보임 | 연결은 됨. 터널 안쪽 문제 | **4장** |

---

## 1. `Missing external certificate`

**원인** — 우리는 아이디/비밀번호로만 접속하는데(개인 인증서 없음), 새 OpenVPN Connect(3.9~)가 개인 인증서를 요구합니다.

**해결** — `.ovpn` 파일을 메모장으로 열어 `remote` 줄 아래에 한 줄 추가:
```
setenv CLIENT_CERT 0
```

> ⚠ **파일만 고치면 반영 안 됩니다.** OpenVPN은 한 번 등록한 프로필을 그대로 씁니다.
> **☰ → 기존 프로필 ⋮ → Remove** 로 **먼저 지우고** → `[Upload File]` 로 다시 가져오세요.

---

## 2. `Trying to connect…` 만 반복

신호가 회사에 못 닿는 것입니다. 위에서부터 확인하세요.

### 2-1. ★가장 흔한 원인 — 사무실 PC를 밖으로 가져감 (`hosts` 고정)

사내 PC는 `PMS_엑셀열기_1회준비_all.bat` 이 `hosts` 파일에 이렇게 적어 둡니다:
```
192.168.0.110  necon-pj.synology.me
```
이 주소는 **사무실 안에서만 통하는 번호**입니다. 밖에서는 세상에 없는 번호라 **벨만 계속 울립니다.**

**진단** (밖에서):
```
ping necon-pj.synology.me
```
응답 주소가 `192.168.0.110` 이면 **원인 확정**.

**해결** — `.ovpn` 의 `remote` 줄을 **이름 대신 숫자 주소**로:
```
remote 222.101.203.90 21194
```
숫자는 아무 데서나 이 명령으로 확인합니다(`hosts`를 건너뛰고 진짜 주소를 물어봅니다):
```
nslookup necon-pj.synology.me 8.8.8.8
```

> **`hosts`는 지우지 마세요.** VPN이 붙고 나면 그 줄 덕분에 NAS 엑셀이 그대로 열립니다.
> 사내에서 쓸 때도 필요합니다. 지우면 사무실에서 [엑셀로 열기]가 깨집니다.

### 2-2. 회사 공인 IP가 바뀜 (유동 IP)

회사 회선은 유동 IP라 **숫자가 바뀌면 같은 증상이 재발**합니다.
→ 위 `nslookup` 으로 새 숫자를 확인해 `remote` 줄만 고치면 됩니다.

> **`hosts`가 없는 PC**(해외 직원·개인 PC)는 숫자 대신 **이름**을 쓰는 게 낫습니다.
> `remote necon-pj.synology.me 21194` — IP가 바뀌어도 알아서 따라갑니다. 파일 재배포가 필요 없습니다.
> 그래서 배포본이 **두 가지**입니다(4-1 표 참고).

### 2-3. 그 밖에

| 확인 | 어디서 |
|---|---|
| 포트가 **21194** 인가 (1194 아님) | `.ovpn` `remote` 줄 |
| 자동 차단에 걸렸나 | DSM → 제어판 → 보안 → **계정** 탭 → 차단 목록 (5회/5분 실패 시 차단) |
| VPN Server 켜져 있나 | DSM → VPN Server → OpenVPN 실행 중 |
| 공유기 포워딩 살아 있나 | Synology Router(192.168.0.1:8001) → 포트 전달 → **외부 21194 → 192.168.0.110:1194 (UDP)** |

## 3. `Authentication failed`

**이건 사실 절반 성공입니다.** 테더링 → 인터넷 → 회사 방화벽 → NAS까지 **신호가 다 갔다**는 뜻입니다. 서버가 대답을 했으니까요. 남은 건 계정 하나입니다.

| 원인 | 확인 |
|---|---|
| 비밀번호가 틀림 | 관리자에게 재확인 |
| **계정에 OpenVPN 권한이 없음** | DSM → **VPN Server → [권한]** → 그 계정 행의 **OpenVPN 열에 체크** |
| 계정이 비활성 | DSM → 제어판 → 사용자 및 그룹 |
| 그 계정에 2단계 인증(OTP)이 켜짐 | OpenVPN은 비밀번호만 보내므로 무조건 실패 → 끄거나 다른 계정 |

> ⚠ **5회 연속 실패하면 그 IP가 자동 차단**됩니다. 2~3번 해서 안 되면 멈추고 위 표를 확인하세요.
> 차단 해제는 **사무실 DSM에서만** 가능합니다(밖에서는 DSM에 못 들어갑니다).

**외부 접속 계정 = `necon-ext`** (공용 1개 · 2026-08-07 팀장 결정).
`necon-kr26` 은 **NAS 관리자 계정**이라 평소 VPN 접속에는 쓰지 않습니다.

## 4. 연결은 됐는데 NAS가 안 보인다

`Securely Connected!` 가 떴다면 아래 순서로 확인하세요. **2026-09-18 실측 통과값**을 같이 적었습니다.

```
ping 192.168.0.110
```
→ 응답 있으면 터널 정상 (실측: 3/3 성공 · 15~152ms)

```
크롬 주소창:  http://192.168.0.110:5000
```
→ DSM 로그인 화면이 뜨면 통과

```
탐색기 주소창:  \\192.168.0.110\NECONSYS_PJ
```
→ `001 Project` · `002 문서관련` · `003 프로그램` · `004 개인 공유 폴더` · `005 PMS Backup` 이 보이면 **완전 성공**

여기까지 되면 PMS에서 **[엑셀로 열기] → 수정 → 저장**이 밖에서도 그대로 됩니다.

---

## 4-1. 배포 파일 — 어느 것을 줄 것인가

| 받는 사람 | 파일 | `remote` 줄 |
|---|---|---|
| **해외 직원 · 개인 PC** (hosts 없음) | `openvpn/VPNConfig_해외배포용.ovpn` | `necon-pj.synology.me` (이름) — IP 바뀌어도 자동 추적 |
| **사무실 PC를 밖으로 가져감** (hosts 있음) | `openvpn/VPNConfig_외부용.ovpn` | `222.101.203.90` (숫자) — IP 바뀌면 갱신 필요 |

둘 다 `setenv CLIENT_CERT 0` 이 들어 있습니다.
원본 `openvpn/VPNConfig.ovpn` 은 **그 줄이 없는 옛 파일**이라 그대로 배포하면 1장 증상이 납니다.

## 5. 실제 사례 기록

### 2026-08-06 — 국내 외부 테스트 성공 (폰 핫스팟)
Connected → DSM → PMS 엑셀 열기·저장 → 탐색기 등록까지 전 구간 통과. 서버 쪽은 이때 이미 정상.

### 2026-08-10 — 해외 직원 실전 2건
- `Missing external certificate` → `setenv CLIENT_CERT 0` 추가 + 프로필 재등록 (1장)
- `Trying to connect` 멈춤 → 사무실 `hosts` 고정 → `remote <공인IP> 21194` (2-1장)

### 2026-08-12 — 집에서 접속 안 됨
소거법으로 차단설·IP변경설 탈락(회사 공인 IP 8/6과 동일). 1순위 = 집에서 쓴 `.ovpn` 이 8/10 수정본이 아닐 가능성. **그대로 미결로 남았다가 9/18에 같은 원인으로 확인됨.**

### 2026-09-18 — 팀장 노트북, 전 구간 성공 ★
- 상태: 사무실 PC를 **폰 테더링**으로 전환 (내 IP 106.101.1.156 = 통신사 IP로 진짜 외부 확인)
- 파일 진단: `remote necon-pj.synology.me 21194` + `setenv CLIENT_CERT 0` **없음** → **두 가지 문제 동시**
- 조치: `remote 222.101.203.90 21194` + `setenv CLIENT_CERT 0` → `VPNConfig_외부용.ovpn` 로 저장, 프로필 재등록
- 1차 시도 `Authentication failed` → 계정 확인 후 **`necon-ext`** 로 재시도 → **`Securely Connected!`**
- 검증: ping 3/3 · 포트 5000·445 열림 · `\\192.168.0.110\NECONSYS_PJ` 폴더 목록 확인
- 부수: 공인 IP는 8/6 이후 **바뀌지 않음**(222.101.203.90 그대로)

## 6. 밖에서 테스트할 때 꼭 지킬 것

1. **랜선을 뽑고 Wi-Fi도 끄세요.** 유선이 살아 있으면 윈도우가 빠른 쪽(사내망)으로 나가서, VPN 없이도 NAS가 보입니다 → **성공했다고 착각**합니다.
2. **테더링 IP를 눈으로 확인하세요.** 네이버 "내 IP" 검색 → `222.101.203.90` 이 **아니어야** 진짜 외부입니다.
3. **비밀번호는 2~3번까지만.** 5회 = 자동 차단.
4. **프로필은 고치기 전에 지우세요.** 파일만 고치면 반영 안 됩니다.
