## 4. 결정·근거 (2026-09-16)
- **1행=1프로젝트로 전환**: 원본 4줄 묶음은 기술팀 파서·병합·백업·엑셀 반영이 못 읽음. 표를 평평하게 하면 기술팀 기능 전부가 코드 추가 없이 그대로 쓰임(팀 카드 방식).
- **진행 현황 값·기입 규칙 (2026-09-16 2차·4차)**: 값 5종 = 수정중·개발중·완료·삭제·Hold. 칩 색 = 수정중 파랑 · 개발중 초록 · 완료 빨강 · Hold/삭제 회색(개발 분류가 칩 색으로도 갈림).
- **진행 현황 자동 따라가기 (4차, 카드 `상태자동`)**: 개발 분류·공정률을 고치면 진행 현황이 규칙대로 같이 바뀐다 — 프로그램 수정 → 수정중 / 프로그램 개발 → 개발중, 공정률 100% 이상 → 완료. 사람이 적어 둔 **완료·삭제·Hold는 자동이 덮지 않는다**(`유지`). 동작 지점 = 셀 키인 · 드롭다운 선택 · 상세/추가 팝업 저장, 그리고 이미 쌓인 행은 설정 **[진행 현황 규칙 맞춤]** 한 번으로 통일(관리자·진행 현황 칸만 저장).
- **진행 현황 입력 방식 (2·4차)**: 2차에는 키인 전용(일반입력열)이었으나 삭제·Hold를 고를 데가 없어 **목록 + [✎ 직접 입력]**으로 바꿈(카드 `일반입력열: []`). 목록 = 마스터 5종 + 그 열에 실제 쓰인 값. [✎ 직접 입력]을 누르면 종전처럼 키인 — 목록에 없는 값도 그대로 저장된다.
- **공정률 단일 열**: 상단 카드·홈 카드는 공용 폴백(‘공정률’ 이름 열 평균)으로 자동 계산. % 막대는 isPctCol에 '공정률' 추가.
- **날짜 키워드 추가**: 공용 isDateCol에 '시작일'·'종료일' — 기술2팀 옛 시트에도 같은 이름이 있어 무해(오히려 달력 지원).
- **메인표 '진행 내용' 여러 줄 (2026-09-16 3차 지시)**: 한 줄로 이어 붙어 읽기 어려움 → 팀 카드 `여러줄열`에 적은 열만 '- ' 항목마다 줄을 나눠 표시(값은 그대로, 보여주기만 나눔). ★메인표 한 줄 펼침 불변 기준(CLAUDE.md)은 다른 팀·다른 열에 그대로 유지. 편집은 엑셀과 동일하게 Alt+Enter(·Shift+Enter) = 줄 추가이며, '- '로 시작하는 줄에서는 새 줄에도 '- '가 자동으로 붙는다. 행 높이가 제각각이 되므로 이 팀은 창 렌더(모든 행 높이가 같다고 보는 속도 최적화)를 끈다(80행 이상에서만 쓰던 기능).
- **과거 연도(2020~2025) 적재는 보류**: 4줄 묶음 서식이라 변환기가 먼저 필요. 카드 `연도별적재:false`.

### 6-2. 진행 기록 팝업 (우클릭 [진행 기록])
- 윗줄 요약 5칸: 시작일(🔒) · 처음 완료예정 · 지금 완료예정 · 지연 · 공정률
- 입력: 날짜(기본 오늘) · 공정률(0~100) · 한 일 → **[적용]** 또는 Enter
- [적용] = **즉시 저장**(초안을 거치지 않음 · 행 문서 merge). 바뀌는 것:
  - 공정률 칸 ← 입력값 (소수 1자리)
  - 진행 내용 맨 아래에 `- 한 일` 한 줄 (옛 한 줄 이어쓰기 ` - `는 먼저 줄로 나눈 뒤 붙임)
  - 공정률 100 → 진행 현황 완료 (4장 자동 규칙 그대로 — 사람이 정한 완료·삭제·Hold는 유지)
  - `_devLog`에 `{kind:'log', date, pct, text, by, at}` 1건 + 변경 이력(`_changeHistory`) + 백로그(수정)
- [완료예정일 바꾸기] 켜기 → 새 날짜 + **사유(필수)** → 완료예정 칸 변경 + `_devLog`에 `{kind:'end', date, from, to, reason, by, at}`
- 막히는 경우: 적은 것이 없음 · 날짜 없음 · 공정률이 0~100 밖 · 새 완료예정일이 비었거나 지금과 같음 · 시작일보다 앞 · 사유 없음
- 그 행에 저장 안 한 노란 칸이 있으면 적용 거부 → 먼저 [저장]/[취소]
- 아래 기록 목록 = 최신이 위(같은 날이면 나중에 적은 것이 위). **기록 삭제·수정 기능은 아직 없음**
- 적다 만 내용이 있으면 [닫기] 때 확인 · 바깥 클릭으로는 안 닫힘(2026-09-15 전 팝업 규칙)

- 지표 5칸: 기간 · 경과 · 남음 · 공정률 · 지연
- 위 막대: 시작일 ~ 지금 완료예정(지난 기간 / 남은 기간) · 점선 = 처음 계획 완료일 · **주황 빗금 = 늘어난 기간** · ◆ = 변경 시점(마우스를 올리면 사유)
- 아래 선: 진행 기록의 공정률(초록 — 시작일 0%에서 출발, 같은 날 여러 번이면 마지막 값) · **'계획대로라면' 점선**(시작일 0% → 처음 완료예정 100%). 초록 선이 점선보다 위면 앞섬, 아래면 늦음
- 빨간 세로선 = 오늘 · 맨 아래 표 = 완료예정일 변경 이력(날짜 · 이전→새 · 늘어난 날 · 사유 · 누가)
- 시작일·완료예정일이 없으면 넣으라는 안내만 표시 · 두 팝업은 버튼으로 서로 왕복

### 6-4. 날짜 규칙
| 규칙 | 내용 |
|---|---|
| 시작일 잠금 | 저장된 시작일은 메인표 키인·범위 Del·상세 팝업 어디서도 바뀌지 않음(메인표 = 안내 토스트 / 팝업 = 🔒 "처음 저장 후 고정"). **관리자만 수정**. 비어 있던 시작일·저장 전 새 행은 적을 수 있음 |
| 처음 완료예정 `_planEnd0` | 완료예정일이 처음 기록될 때(진행 기록 적용 · 완료예정 칸 저장) 그때의 날짜를 보관, 이후 불변. 보관값이 없으면 지금 완료예정으로 대신(지연 0) |
| 지연 | 지금 완료예정 − 처음 완료예정 (일). + = 늦어짐(주황) |
| 메인표에서 변경 | [저장] 때 바뀐 행을 모아 사유를 **한 번** 물음 — 빈칸 = '표에서 변경' · [취소] = 저장 보류(노란 칸 유지) |
| 상세 팝업에서 변경 | [저장] 때 사유를 물음 — 빈칸 = '상세 팝업에서 변경' · [취소] = 저장 안 함(팝업 유지) |
| 이력이 남는 조건 | 이전·새 날짜가 **둘 다 있고 다를 때만** (빈칸 → 첫 입력은 이력 아님) |
| 엑셀 | [엑셀 반영]·[엑셀 확정 저장]으로 들어온 완료예정일은 '엑셀 절대 우선' — 이력 없이 엑셀 값으로 바뀜 (엑셀에 옛 날짜가 남아 있으면 웹에서 바꾼 날짜가 되돌아가므로 엑셀도 같이 고칠 것) |

### 6-5. 저장 위치 · 주의
- 기록은 행 문서 안 내부 필드(`_devLog`·`_planEnd0`) — 표 열이 아니라서 메인표·[엑셀 생성]에는 나오지 않는다
- **남는 경로**: [엑셀 반영]·[엑셀 확정 저장] = 둘 다 보존 병합(`computeMergePlan` — 기존 행 전체를 복사한 뒤 엑셀 열만 덮어씀, `projectListData.js` 186~192행)
- **사라지는 경로**: [연도별 1:1 적재](그 해 통째 교체) · [데이터 삭제] · [백업 복원](복원 시점 상태로 되돌림). 실행 전 백업

### 7-2. 연도 판정
- **그 파일이 든 폴더 이름 = 그 해** (팀장님 2026-09-18: "2020년 엑셀에 있으면 2020년이라고 판단해")
- 12월분을 다음 해 1월에 쓴 파일(`월간보고_260106_12월_SW.xlsx`)도 **그 해(2025)** 로 본다
- 2025 폴더 총정리본은 **탭 이름이 '2024년…'로 남아 있다** — 탭이 아니라 시트 제목(A1)의 연도를 믿는다

### 7-3. 날짜 해석

### 7-4. 이름 — 합치지 않는다

- 근거(실측): 닮은 정도 84~88%에서 「CO ESS」·「CO E-SPC」·「CO E-FDC」(서로 다른 시스템), 「파주 CDA」·「CA CDA」(다른 공장)가 잘못 묶였다. 짧은 기술 이름은 한 토막만 달라도 다른 일이다
