## 파서 실측 보정 (2026-08-11 오후 — 실제 웹 파서로 검증한 결과)

- **유효 열 = 43개** (44열 중 2칸은 '그룹 병합 이어짐 + 세부 이름 없음'이라 파서가 자동 제외 — ① 비고 [ISSUE] 둘째 칸 ② 관련공사 끝 빈 칸. **전수 확인 결과 두 칸 모두 데이터 0건 = 손실 없음**).
- **유효 행 = 12건** (순번+공사명 AND 규칙 — 하단 집계표 4행·템플릿 행 자동 탈락. 위 '원본 구조' 참고).
- 비고는 **'비고 [ISSUE]' 1칸**으로 들어옴 (둘째 칸 제외 — 위와 같은 이유. 데이터 2건은 첫 칸에 있어 전부 보존).
- 중복 열 이름('일자'·'업체명'·'담당자')은 현행 규칙대로 **두 번째부터 '(2)' 붙여 구분** (그룹명 붙이기는 3단계 화면 확인 때 필요하면 검토).
- 줄바꿈 헤더는 공백으로 정규화되어 카드와 일치: 'ETOS\nT/S'→'ETOS T/S', '자체\n시운전'→'자체 시운전'.
- 검증: 시트 "2026 (2)" 단독 선택(43열 > "2026" 28열) · 12행 · 순번 01~12 연속 · 수행번호 원문 유지(26-01, 무패딩) — 자동 시뮬 11/11 + 기존 팀 회귀 30/30 통과.
- 상태 실측(12건): 계약 = 수주 7 · 취소 2 · 견적 1 · 예상 1 · 패찰 1 (전부 채움) / 작업 = 완료 5 · 미작업 2 · 빈칸 5.

## 업로드(파서) 규칙 — 기술1팀 프로파일 전용

1. **시트 선택**: 최신 연도 시트가 여러 개면 **열이 가장 많은 것 하나만** 사용 ("2026"+"2026 (2)" 중복 적재 방지 — 현재 규칙은 둘을 합쳐 16건→32건이 되는 함정).
2. **헤더**: 행1(제목)·행2(Update)는 장식 → **행3(그룹)+행4(세부) 2층 헤더**로 해석. 현재 공용 파서는 행2를 그룹으로 오인할 수 있음 → 프로파일에서 헤더 시작행 지정.
3. **행 유효성**: **순번+공사명 둘 다 있어야 데이터 행** — 템플릿 행(순번만)은 공사명에서, 하단 집계표(공사명 칸에 라벨만)는 순번에서 탈락 (2026-08-11 실측 보강).
4. **날짜**: 원문 보존, 변환 없음.
5. **중복 열 이름**: '일자'·'업체명'·'담당자'·'비고' 중복 → 그룹명 붙여 구분(기존 중복 헤더 규칙 확장).
